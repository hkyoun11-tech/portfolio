브루라인 ERP

오피스 상권 카페의 판매, 재고, 구매, 원가, 수요 예측을 하나로 잇는 ERP 프로토타입입니다. 메뉴를 눌러 직접 써보세요.

모든 수치는 가상 데이터이며 새로고침하면 초기화됩니다.

    브루라인 ERP는 오피스 상권 카페 한 곳의 판매, 재고, 발주, 원가를 하나의 데이터로 잇고, 날씨와 요일로 오늘 올 손님 수를 예측하는 경량 ERP 설계입니다.

    역할
    기획, 프로세스 설계, 화면 설계, 프로토타입 구현
    출발점
    산업경영공학과 ERP 수업의 커피 프로세스 과제
    데이터
    카페 설정부터 수치까지 모두 가상 데이터
    프로토타입으로 돌아가기 설계 과정 읽기

    사장님의 감이 유일한 시스템일 때

    대상은 가상의 카페 ‘모닝톤 커피’입니다. 오피스 빌딩 1층에 있고, 평일 하루 손님은 300명 안팎, 사장 1명과 파트타이머 1~2명이 운영합니다. 출근 시간과 점심 직후에 손님이 몰리고, 주말에는 평일의 3분의 1 이하로 줄어드는 오피스 상권의 전형적인 리듬으로 설정했습니다.

    이런 가게에서 반복되는 문제는 세 가지로 정리했습니다.

    발주가 기억에 의존한다

    원두와 컵이 떨어지기 직전에야 주문하고, 도착까지 며칠 걸리는 품목은 한 번씩 품절이 납니다.

    우유는 늘 많거나 모자란다

    유통기한이 짧아 넉넉히 사면 버리게 되고, 아껴 사면 점심 피크에 바닥납니다.

    매출과 재고가 따로 논다

    POS에는 매출만, 엑셀에는 재고만 있어서 “라떼가 많이 팔려 우유가 줄었다”는 연결을 사람이 직접 해야 합니다.

    위 상황은 이 프로젝트를 위해 설정한 가상 시나리오이며, 실제 매장 조사 결과가 아닙니다.

    여기에 날씨를 더한 이유

    날씨는 손님 수보다 손님이 고르는 음료를 더 크게 바꿀 수 있습니다. 미국의 한 대학 카페 데이터를 다룬 교육 자료에서는 기온이 오를수록 커피는 덜 팔리고 탄산음료가 더 팔렸지만 전체 판매량은 크게 변하지 않아, 같은 손님이 따뜻한 음료에서 차가운 음료로 옮겨간 것으로 해석했습니다. 아이스 비율이 바뀌면 얼음과 아이스컵, 우유 사용량이 함께 바뀌기 때문에, 예측은 결국 재고와 발주 문제로 이어집니다.

    흩어진 세 개의 기록을 하나의 고리로

    지금은 매출, 재고, 발주가 각자 다른 곳에 기록되고 서로 연결되지 않습니다.

    개선안은 이 기록들을 하나의 데이터베이스에 두고, 한 단계의 결과가 다음 단계의 입력이 되도록 순서를 설계했습니다. 색으로 표시한 4~5단계가 사람의 손을 가장 많이 덜어주는 구간입니다.

    1. 예측날씨와 요일로 오늘 손님 수와 메뉴별 수요 계산
    2. 준비필요한 우유, 얼음, 원두 양과 근무 인원 제안
    3. 판매POS 주문 1건 기록
    4. 차감레시피대로 재료 자동 차감, 우유는 유통기한 빠른 것부터
    5. 감지재주문점 아래로 내려간 품목을 발주 제안으로 생성
    6. 발주와 입고제안 승인, 입고 검수 후 재고 반영
    7. 학습실제 판매량이 다음 예측의 입력값이 됨

    7단계에서 쌓인 실제 판매량은 다시 1단계 예측 모델의 ‘지난주 같은 요일 손님 수’로 들어갑니다.

    7개 업무 메뉴, 14개 화면

    처음 설계한 8개 모듈을 실제 ERP의 메뉴 체계로 다시 묶었습니다. 판매 등록, 재고 현황처럼 매일 쓰는 화면 옆에 재고 수불부, 입고 처리, 거래처와 품목 마스터처럼 ERP라면 기본으로 갖추는 화면을 더했습니다. 모든 화면에는 업무 영역 약자와 번호로 된 화면 ID를 붙여, 운영 문의나 권한 설정 때 화면을 정확히 가리킬 수 있게 했습니다.

    화면 공통 규칙

    같은 순서로 읽히게

    모든 업무 화면은 경로와 화면 ID, 툴바, 조회조건, 데이터 그리드, 합계 행 순서로 배치했습니다. 화면이 바뀌어도 눈이 가는 위치가 같아서 처음 쓰는 직원도 빨리 익힙니다.

    여러 화면을 동시에

    메뉴를 열 때마다 상단에 탭이 쌓입니다. 발주를 승인하다가 재고 현황을 확인하고 다시 돌아오는 ERP 사용 패턴을 그대로 지원합니다.

    색은 장식에 쓰지 않고 상태와 온도에만 썼습니다.

    단순하지만 설명할 수 있는 예측

    예측 모델은 딥러닝 대신 다중회귀로 정했습니다. 2025년 한 연구는 날씨와 판매 데이터로 여러 모델을 비교했는데, SARIMA나 LSTM보다 OLS와 포아송 회귀 같은 회귀 모델이 더 좋은 결과를 냈고, 기온과 습도는 판매량과 중간 정도의 상관을 보였지만 날씨만 단독으로 쓰면 예측 기여가 제한적이었다고 보고했습니다. 그래서 날씨 외에 요일, 공휴일, 지난주 같은 요일의 실적을 함께 넣었습니다. 사장님에게 “왜 오늘 280명인가”를 숫자 하나하나로 보여줄 수 있다는 점도 회귀를 고른 이유입니다.

    예상 손님 = β₀ + β₁·지난주 같은 요일 + β₂·(최고기온 − 20) + β₃·비 + β₄·미세먼지 나쁨
    계수의미값 (가상)
    β₀기본값18
    β₁지난주 같은 요일 손님 1명당0.88
    β₂20℃보다 1℃ 높을 때마다+0.9명
    β₃비 오는 날−24명
    β₄미세먼지 나쁨 이상−16명

    공휴일에는 ‘지난주 같은 요일’ 대신 주말 평균을 넣습니다. 계수는 프로토타입 시연을 위한 가상값이고, 실제 도입 시 매장 데이터로 다시 추정해야 합니다.

    미세먼지를 변수로 넣은 데는 국내 연구도 참고했습니다. 세탁 서비스 매출을 분석한 연구에서는 기온이 아니라 강수량과 미세먼지, 초미세먼지가 매출에 통계적으로 유의한 영향을 줬습니다. 업종마다 영향을 주는 날씨 요소가 다르다는 뜻이라, 카페에서도 기온 하나만 보지 않도록 설계했습니다.

    핫과 아이스 비율

    손님 수와 별도로, 최고기온에 따라 아이스 음료 비율을 S자 곡선으로 계산합니다. 14℃에서 절반이 되도록 두고, 한국은 한겨울에도 아이스 수요가 꾸준하다는 점을 반영해 최저 35%, 최고 95%로 제한했습니다. 스타벅스코리아가 2023년에 공개한 자료에서도 매출 기준 1위 메뉴가 아이스 아메리카노였습니다. 이 비율이 얼음, 아이스컵, 빨대의 예상 사용량을 바꿉니다.

    재주문점과 안전재고

    “언제 주문해야 품절이 나지 않는가”는 생산운영관리에서 다루는 표준 재고 모형으로 계산했습니다.

    안전재고 = z × σ × √L
    재주문점 = 하루 평균 사용량 × L + 안전재고

    z는 품절을 피하고 싶은 확률(서비스 수준 95%면 1.65), σ는 하루 사용량의 표준편차, L은 주문 후 도착까지 걸리는 일수입니다. 프로토타입에서는 σ를 하루 평균 사용량의 18%로 가정했습니다.

    발주량은 “목표 재고 − 현재고”를 포장 단위로 올림해 정합니다. 목표 재고는 리드타임에 다음 발주까지의 3일을 더한 기간의 사용량과 안전재고를 합친 값입니다.

    실제 날씨를 연결한다면

    기상청이 공공데이터포털에 제공하는 단기예보 조회서비스를 쓰는 구조로 설계했습니다. 무료이고 개발 계정은 10,000건까지 자동 승인되며, 위치는 위경도가 아니라 기상청 격자 좌표(nx, ny)로 요청합니다. 인증키를 웹페이지에 그대로 넣으면 누구나 볼 수 있으므로, 실제 운영에서는 작은 서버가 하루 몇 번 예보를 받아 저장하고 화면은 그 결과만 읽게 합니다. 이 프로토타입은 키 노출을 피하기 위해 날씨를 시나리오로 직접 고르는 방식입니다.

    한계와 다음 단계

    계수는 가상값입니다

    실제 도입이라면 POS 판매 기록과 일별 날씨를 8~12주 모은 뒤 회귀 계수를 추정하고, 마지막 몇 주는 학습에서 빼 두었다가 MAPE(평균 절대 백분율 오차)로 예측이 얼마나 빗나가는지 확인하겠습니다. 목표 오차는 운영자와 함께 정해야 할 값이라 이 설계에서 미리 정하지 않았습니다.

    레시피와 실제 사용량은 다릅니다

    바리스타마다 우유를 따르는 양이 조금씩 다르기 때문에, 이론 재고와 실제 재고 사이에 차이가 생깁니다. 주 1회 실사로 재고를 맞추고 그 차이를 로스로 기록해, 레시피 사용량을 보정하는 절차가 필요합니다.

    POS 연동은 별도 협의가 필요합니다

    판매 자동 차감은 POS사가 주문 데이터를 내보내는 API를 제공해야 가능합니다. 연동이 어려운 매장을 위해 마감 후 판매 수량을 한 번에 입력하는 방식도 함께 고려했습니다.

    돌아보며

    처음에는 회계, 인사, 고객 관리까지 화면을 늘리고 싶었지만, ERP의 핵심은 기능의 수보다 기능 사이의 연결이라는 점을 기준으로 범위를 줄였습니다. 판매 1건이 재고와 발주까지 이어지는 장면을 직접 눌러볼 수 있게 만든 것이 그 결정의 결과입니다.

    AI 예측도 숫자 하나만 크게 보여주기보다, 그 숫자가 기본값, 지난주 실적, 기온, 비, 미세먼지에서 각각 얼마씩 나왔는지 막대로 쪼개 보여주는 쪽을 택했습니다. 사장님이 예측을 믿고 발주하려면, 결과보다 근거가 먼저 보여야 한다고 생각했기 때문입니다.

    기획, 설계, 구현 윤희경. 카페 설정과 모든 수치는 가상 데이터입니다.
